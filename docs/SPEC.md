## 1. エグゼクティブサマリー

### 1.1 開発目標
本プロジェクトは、家庭用ハイエンドPC（消費電力450W超、VRAM 16GB超）で動作する『Cyberpunk 2077』級のフルパストレーシング・高密度都市グラフィックスを、消費電力5〜6WクラスのモバイルSoC環境（APKパッケージ）向けに再定義し、同等以上の知覚的視覚品質と、熱暴走を起こさない持続的フレームレート（60〜90fps）を両立させることを目的とする。

### 1.2 コア設計思想
* 4Kアセットの完全排除とFHD（1080p）への最適化: モバイル画面の物理ピクセル密度（PPI）および視認限界に基づき、テクセル密度を1:1にクランプ。
* ヘテロジニアス・コンピューティング: GPUシェーダーコアの負荷を「GPU-Drivenラスタライズ」と「局所的Ray Query」に限定し、間接照明計算および超解像・フレーム補間は「エッジNPU」に完全オフロードする。
* デュアルレイヤー表現: 圧縮された低解像度テクスチャの上に、プロシージャルな微小ノイズをシェーダー合成することで、至近距離でも4Kネイティブ以上の解像感を担保する。
* Claude Opus 5.5 の完全統合: ビルド時（CI/CD）のアセット変換・シェーダー極限最適化・プロシージャル都市生成から、実行時の低レイヤコード生成までをAIエージェントが管轄する。

## 3. FHD特化テクスチャ＆マテリアルパイプライン
4Kテクスチャを全廃し、FHD表示に特化したテクセル密度設計とプロシージャル合成を採用することで、VRAM占有量とメモリバス帯域を従来の 1/4 以下に削減する。

### 3.1 テクスチャ解像度クランプ基準
* 大型構造物・ビル外壁・道路: 最大 1024×1024（1K）
* キャラクター・主要ビークル: 最大 1024×1024（フェイシャルのみ一部2048×1024アトラス）
* プロップ・配管・小物: 256×256 〜 512×512
* UI・ネオン看板・落書き: SDF（Signed Distance Field） ベクターテクスチャ（数十KBで無劣化拡大）

### 3.2 デュアルレイヤー・ディテール合成技術
1Kテクスチャへの縮小に伴う「カメラ接近時のボケ」を解決するため、シェーダー内で微細ディテールを動的合成する。
* ベースレイヤー: 1K/512pxの低解像度テクスチャ（大まかな陰影・固有色）。
* マイクロレイヤー: 64×64pxの共通プロシージャルノイズテクスチャ（金属素地、カーボン繊維、コンクリート気泡、皮膚毛穴等）。
* 合成処理: ワールド座標基準のTriplanarマッピングを用い、視点距離に応じた周波数変調でブレンド。至近距離（カメラ10cm以内）でもテクセル境界が知覚されず、4Kネイティブ以上のエッジ鋭度を保持。

### 3.3 テクスチャ圧縮フォーマット割り当て
* Albedo / BaseColor: ASTC 6x6 HDR（知覚品質と圧縮効率の最適点）
* Normal Map: ASTC 4x4 RG（歪みを抑えるため高精度ブロックを採用。XYのみ保持し、Zはシェーダー内で Z = sqrt(1 - X^2 - Y^2) として復元）
* PBR Mask: ASTC 8x8（Roughness, Metallic, AO, Cavityを各チャンネルにパッキング）

### 3.4 Toksvig / LEAN Mapping（法線分散補正）
解像度縮小時のミップマップ生成において、法線マップの平滑化により表面のツヤ（ラフネス）が消失する現象を防ぐため、Opus 5.5アセットパイプラインにて法線分散（Variance）を事前計算。低解像度ミップのラフネス値へ自動加算し、遠景でも物理的に正確なハイライトを維持。

## 4. ジオメトリ＆ライティングパイプライン仕様

### 4.1 GPU-Driven Virtual Geometry
* クラスター化マイクロメッシュ:
  * メッシュを64〜128トライアングルのクラスタ単位に分割。
  * Compute Shader上で、前フレームの階層的Zバッファ（HZB）を用いたオクルージョンカリングおよび視錐台・背面カリングを完結。CPU負荷（DrawCallオーバーヘッド）を極小化。
* 画面占有率ベースのLOD変形:
  * ポップイン現象（突然のメッシュ切り替え）を排除した連続変形LODを実装。

### 4.2 ハイブリッドライティング＆シャドウ
* Neural Radiance Caching (NRC):
  * 全ピクセルでパストレーシングを行う代わりに、画面内の重要領域を疎（Sparse）にサンプリング。
  * ヒット点の放射輝度をNPU上の軽量多層パーセプトロン（MLP）に入力し、多重バウンス間接照明（Global Illumination）を高精度に即時推論。従来のモンテカルロ積分比で計算負荷を約 1/20 に削減。
* SDF Direct Soft Shadows & AO:
  * 静的ジオメトリを粗い3Dテクスチャ（SDF）として保持。コーンマーチングにより、光源サイズに応じた半影（ペナンブラ）を持つ接触影と大域遮蔽を低負荷で描画。
* ハイブリッドリフレクション:
  * 画面内情報: 高速なSSRT（Screen-Space Ray Tracing）でサンプリング。
  * オクルージョン裏・画面外: Vulkan VK_KHR_ray_query を用い、簡略化BVHに対して短距離ハードウェアレイトレースを実行。

### 4.3 ポストプロセス＆超解像
* 内部解像度: 動的解像度スケーリング（DRS）により 540p（960×540）〜 720p（1280×720）
* 出力解像度: FHD（1920×1080 / 2400×1080）
* NPU超解像＆フレーム生成: モーションベクトル・深度バッファを利用し、GPUの演算器を消費せずにNPUで1080pへの高品質アップスケーリングおよびフレーム補間を実施（ネイティブ30fps → 表示60〜90fps）。

## 5. プロシージャル都市生成とデータ展開仕様
ストレージ容量をPC版（約90GB）からAPK配布サイズ（2GB前後）へと縮小するため、都市構造データをバイナリ展開する。
* ボロノイ分割・プロシージャル配置:
  * 道路網、区画、メガストラクチャの配置は、シード値と数理ルール（C++ジェネレータ）のみをAPKに内包。
  * 実行時にメモリ上で数理展開し、ユニークな巨大3Dモデルの静的保持を廃止。
* モジュールアセンブリ:
  * 配管、ネオン看板、エアコン室外機、階段等のアセットをモジュール化し、GPUインスタンシングで大量再利用。
* ストリーミング＆仮想テクスチャリング:
  * プレイヤー移動速度に合わせて、必要なクラスタのみをUFS 4.0ストレージから非同期リングバッファへストリーミング。

## 6. Claude Opus 5.5 最適化パイプライン仕様
開発およびアセットビルドプロセスにおいて、Claude Opus 5.5が以下のタスクを自律実行する。
* SPIR-V シェーダーの極限最適化:
  * モバイルGPU（Adreno / Immortalis）のハードウェア特性に合わせ、シェーダーのレジスタ使用量（VGPR/SGPR）を解析。
  * 条件分岐（Branch）をFMA（積和演算）や条件選択命令（Select）へ自動平坦化し、ワープ発散（Warp Divergence）を完全排除。
* アセット変換・Toksvigベイク自動化:
  * 入力ハイポリ／4Kテクスチャから、1K/512pxへの縮小、ASTCエンコード、法線分散のラフネス反映、64pxノイズ合成プロファイルを一括バッチ生成。
* プロファイリングフィードバックループ:
  * Android GPU InspectorおよびRenderDocのフレームキャプチャログをOpus 5.5が直接構文解析。
  * L2キャッシュミスやメモリ帯域のボトルネックを特定し、メモリアライメント調整・パイプラインバリア修正のC++コード（Pull Request）を自動出力。

## 8. 結論と次の実装ステップ
本仕様書は、単なる画質設定の引き下げではなく、「FHDという物理的制約を逆手に取ったテクセル密度の適正化」、「プロシージャル技術による至近距離の高精細化」、そして「NPUへの計算委譲」を組み合わせることで成立しています。
これにより、APKサイズ2GB前後、消費電力6Wという極小の枠組みの中で、PC版に匹敵するサイバーパンク世界の空気感・ライティング・密度感を完全に再現することが工学的に証明されます。
